⚙️ Code-grounded findings that reshaped the draft

  • Betrayal and Shared-Danger are the same moment. When an ally hits NEAR_DEATH in combat, one party member's DEFEND_ALLY already writes a SAVED_BY history token (→ OWES belief); a HESITATE writes BETRAYED_BY (→ DISTRUSTS). Both tokens already exist and move zero relationship strength. The two "opposite" drivers are one trigger surface.
  • There is no loot split. Quest loot is a single number added to the guild treasury - never divided among party members. So betrayal-over-spoils and rivalry-over-credit, as the draft describes them, have no mechanical surface.
  • There is no inventory. Adventurers own no items. A "gift" cannot be an object transfer - it must be an abstract gesture, or the driver needs rethinking.
  • Divine bias has no hook. pendingShifts only feeds decision-moment outcomes; nothing biases a social-driver probability. The draft's per-driver "divine bias" bullets are aspirational.

Branch 1 · Framing (gates everything below)

Q1

Unify Betrayal + Shared-Danger into one "peril response" trigger?

ROOT DECISION

The draft treats them as two independent drivers. But the code shows they're two responses to the same event: an ally at death's door. The machinery already fires SAVED_BYexists and BETRAYED_BYexists - both dead-end tokens that colour thoughts but never touch the bond.

Ally hits NEAR_DEATH
combat beat, already emitted
→
DEFEND_ALLY
writes SAVED_BY · SHARED_DANGER bond (+)
HESITATE / walk away
writes BETRAYED_BY · BETRAYAL (−)
AUnify: one peril-response detector with a positive (defended) and negative (abandoned) branch. Wires both dead-end tokens in one place.
BKeep them as two independent drivers per the draft, each with its own detection.
Recommend · A

The trigger surface is literally one event. Unifying makes the code honest, wires SAVED_BY and BETRAYED_BY together, and yields a tighter narrative ("who stood by you when it counted"). Betrayal outside combat (a cold RIVAL turning) can still exist as a rarer second path if we want it - but the primary anchor is peril response.

Q2

What is a "gift" with no inventory or personal economy?

depends: framing

No items, no personal coin - loot goes to the guild. A literal gift is unmodellable. Meanwhile the social system already produces SOLIDARITY and BREAKTHROUGH positive encounters. So: is a distinct positive driver even needed, and if so what is it?

AReframe as an abstract act of kindness / favour (covers a shift, a vouch, tending an injury) - generosity-driven, distinct from an ambient chat because it's a deliberate one-sided gesture.
BCut the positive town-life driver for v1 - lean on SHARED_DANGER + existing SOLIDARITY/BREAKTHROUGH encounters for warmth.
CKeep "gift" literally and build a minimal token/coin economy first (large scope add).
Recommend · A (leaning B if we want a smaller v1)

Reframe to a generic kindness/favour gesture so it has diegetic meaning without an economy. But flag the real question: does it earn its place next to SOLIDARITY? If the distinction feels thin, defer it (B) and ship 3 drivers. C is out - it violates the "refinement, not new pillars" appetite.

Q3

Is the driver taxonomy complete - and is a new event kind right?

depends: Q1, Q2

The graph already fires RECONCILIATION as a threshold event, so "forgiveness" needn't be a driver. And the surfacing choice: a new RELATIONSHIP event kind vs. extending the existing SOCIAL outcome set.

AFinal set = { peril-response(±), kindness, rivalry-spark }. New RELATIONSHIP kind for clean feed-filtering.
BFold drivers into SOCIAL as new outcomes - no new kind, less surface.
Recommend · A

Drivers are causes tied to quests/combat/deliberate acts, not pressure-discharge scenes - conflating them with SOCIAL muddies both. A distinct kind keeps the feed filter meaningful. RECONCILIATION stays a threshold event, not a driver.

Branch 2 · Trigger mechanics

Q4

Betrayal's non-combat path - keep it, and on what surface?

depends: Q1

With loot-theft off the table, does betrayal fire anywhere outside peril? Candidate: a RIVAL/strained edge under mood pressure "turning" - but that risks overlapping ESTRANGEMENT.

APeril-abandonment only for v1. Simplest, fully grounded.
BPeril + a rare "cold turn" on a strained RIVAL edge (needs a de-dupe rule vs ESTRANGEMENT).
Recommend · A

Ship the grounded path first; the "cold turn" risks double-firing with ESTRANGEMENT. Add B later if betrayal feels too combat-locked.

Q5

Rivalry-spark's "contested context" - what data backs it?

depends: Q2

questVolunteerWeight already computes goal-alignment (personalGoal × quest type)exists. So "both want the same quest / same goal" is derivable. Spoils-dispute is not (no split).

Recommend

Trigger on same-goal / same-quest competition between two high-ambition low-empathy actors, plus mood-strain. Drop "credit/spoils dispute" language - unbuildable.

Q6

Delta magnitudes & frequency - do they balance against what exists?

depends: Q1,Q3

Anchors already in the graph: co-quest +8, SOLIDARITY +10, BREAKTHROUGH +18, ESTRANGEMENT −22. Draft drivers: SHARED_DANGER +12/+18, BETRAYAL −18/−6, kindness +4/+7, rivalry −10/−14.

Recommend

Magnitudes look coherent (peril > ambient; betrayal near estrangement). The real risk is frequency: 3-4 drivers + existing encounters could flood the feed. Lock a per-pair cooldown (draft: once/day + jitter) and validate aggregate feed volume over a 30-day seeded run as an explicit test.

Branch 3 · Influence, surfacing, NPCs

Q7

Divine influence over drivers - v1 scope?

independent

No hook biases social-driver odds today. But existing effects (MOOD_LIFT, COURAGE_BLESS) already move the mood/axes that feed the trigger formulas - so indirect influence is free; direct bias is new wiring.

Av1 = purely autonomous; influence only indirect via existing effects. Delete per-driver "divine bias" promises from the spec.
BBuild a dedicated driver-probability shift now.
Recommend · A

Indirect influence already satisfies "the player can nudge, never trigger" and needs no new mechanism. Trim the spec's overpromise; revisit direct bias only if playtest wants it.

Q8

Drift indicator - right surface, or clutter?

depends: Q3

Per-row ▲/▼/– glyph + recent-cause, derived from 7-day edge history. Adds a moving element to every relationship row.

Recommend

Keep it, but show the glyph only when non-steady (a warming/cooling bond), and hide on settled edges - so it reads as signal, not decoration. Confirm TREND_EPS and window (7d) are tunable constants.

Q9

NPC participation boundary under the unified model

depends: Q1

NPCs aren't in combat and don't quest - so peril-response (the primary betrayal/shared-danger path) can't involve them. That leaves NPCs only kindness + rivalry (town-life drivers).

Recommend

Make explicit: NPC-eligible drivers = kindness + rivalry-spark only; peril-response is adventurer-only (consistent with the no-quest exclusion). Update relationship-events.md §NPC participation accordingly.
