The top-bar clock and the spread header show different dates

After every Proceed, the top-bar clock and the cycle spread you're reading disagree by one cycle. The spec (app-shell.md:25) says the clock is "the cycle just read" - but the code shows the cycle you're poised on. One of them is wrong. This is a wording fork, not a bug in the sim.

1 Why they can't both be right

At any rest state the shell names a cycle in three places. Two of them are inherently one cycle apart - the spread reports what you just read; the button names where the next Proceed lands. The clock sits between them and can cheaply match only one neighbour. So the real question is: which neighbour should the clock agree with?

5 My recommendation

Option B - keep the code, fix the spec wording

The top bar is a clock: its job is to say where the world is, and it's the one element that visibly ticks forward on every Proceed. Option A's clock stalls on the same date until you Proceed again, which reads as a broken clock.

The spread header already carries the "what you just read" date, so making the clock echo it is redundant - two labels saying the same thing. That leaves Option B a one-line spec wording fix with zero code churn. Option C solves a contradiction that mostly disappears once the spec stops claiming the clock is "the cycle just read".
